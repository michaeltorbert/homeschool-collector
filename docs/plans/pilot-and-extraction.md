# Usefulness and optional public-text extraction evaluation

Proposed. Parent judgement establishes worthwhile discovery, wrong age/interest predictions, missing sources, noise and repeat-review burden; counts/tests/consensus do not. Start from the explicit-settings baseline, label uncertainty and preserve access to excluded/passed/changed evidence. Use consented minimal local pilot observations; do not publish real profile, note, calendar or private-group data. Separate source coverage failures from scoring/fit errors. Evaluate seasonal behavior before proposing recency decay or more infrastructure.

Age-specific public grammar measurement is mandatory in issue #2, not duplicated here. Later semantic extraction requires an explicit service/data decision. No model is required for the current implementation or initial deterministic learner. Build a public/synthetic labeled evaluation set, with supported/unsupported quotes, audience versus rules, roles/supervision, ambiguous/reference conflicts, venue false positives, missing fields and malicious source instructions.

Model proposals must pass schema, exact quotation/span and semantic entailment checks; a matching span alone is not authority. Supported literal rule grammars are reparsed deterministically. Unsupported/contradictory/failed extraction yields unknown. Only code computes birthdays/references/exclusions/constraints/scoring/expiry/cache identities. Public listing extraction never receives private profiles, household identifiers/history/free-text notes or private calendar details; group text is not public simply because Muse supplies it. Source text remains data. Service access/cost/availability and safe logging/redaction need verification before implementation/provisioning.

Acceptance: document evaluation criteria, reproducible synthetic/public cases and failure/unknown rates without fabricated eligible yield; parent usefulness/review-burden measures distinct from technical correctness; test injection/malformed/schema-valid-but-unentailed output and conservative failure behavior; preserve baseline, source/notice/Undo rules. Any proposed learning thresholds, numeric fit modifiers or recency changes require measured rationale, visible controls and corresponding issue/spec revision. No automatic provider/model purchases or outreach.
